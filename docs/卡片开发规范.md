# dsDock 卡片开发规范

> 面向：给「桌面备忘录（dsDock）」写卡片插件的人（包括我们自己）
> 依据：当前代码的实际行为（`src/DsDock.Card.Abstractions`、`Plugins/`、`src/Cards/Clock`、`src/Cards/StickyNote`）

---

## 1. 一张卡片是什么

卡片 = **一个独立 DLL 插件**。宿主（DsDock.exe）在启动时：

1. 读应用根目录的 `registry.json`，拿到"已注册的卡片 id 列表"
2. 对每个 id 去 `Cards/<id>/` 找 `manifest.json` 并**校验**
3. 校验通过 → 为它建一个**独立的 `AssemblyLoadContext`** 加载 `entry` 指定的 DLL
4. 反射找 `ICardFactory` 实现 → 交给容器按需创建实例

**关键约束**：宿主的加载是"失败隔离"的 —— 某张卡片清单非法、DLL 缺失、加载抛异常，都只会**跳过这一张并记录原因 + 弹一次系统气泡**，其它卡片照常工作。所以卡片不需要考虑"别把宿主搞崩"，但要保证自己的 DLL 能独立加载。

## 2. 目录与文件

### 运行时（应用根目录，用户可见，由构建脚本生成）

```
应用根目录/
├─ DsDock.exe
├─ registry.json                 {"cards":["clock","sticky_note"]}
└─ Cards/
   ├─ clock/
   │  ├─ manifest.json
   │  ├─ ClockCard.dll
   │  └─ icon.png
   └─ sticky_note/
      ├─ manifest.json
      ├─ StickyNoteCard.dll
      └─ icon.png
```

- 目录名**必须等于 `manifest.id`**（构建脚本按 `id` 决定目标目录名，不是按源码文件夹名）
- 应用根 = `DsDock.exe` 所在目录；若 exe 在 `bin/...` 下，宿主会逐级向上找含 `registry.json` 的目录作为部署根

### 源码（仓库里）

```
src/
├─ DsDock.Card.Abstractions/     卡片契约（宿主与所有卡片共同引用）
└─ Cards/
   ├─ Clock/       DsDock.Cards.Clock.csproj + ClockCard.cs + manifest.json + icon.png
   └─ StickyNote/  DsDock.Cards.StickyNote.csproj + StickyNoteCard.cs + manifest.json + icon.png
```

## 3. `registry.json`

```json
{ "cards": ["clock", "sticky_note"] }
```

- 只罗列**已注册**的卡片 id；卡片库只显示注册过、且清单校验通过、且加载成功的卡片
- 构建脚本会双向校验：注册了但没构建 → 警告；构建了但没注册 → 不暂存

## 4. `manifest.json` 字段与校验规则

```json
{
  "id": "clock",
  "name": "时钟",
  "version": "1.0.0",
  "entry": "ClockCard.dll",
  "icon": "icon.png",
  "description": "显示当前时间日期",
  "allowedSizes": ["1x1", "2x1"],
  "defaultSize": "1x1",
  "maxInstances": 1,
  "minAppVersion": "1.0.0"
}
```

| 字段 | 必填 | 规则（宿主实际校验的） |
|---|---|---|
| `id` | ✅ | 非空；**必须与 `registry.json` 里的 id、目录名、`ICardFactory.Id` 三者一致** |
| `name` | ✅ | 非空，显示在卡片库/卡片菜单 |
| `version` | ✅ | 形如 `1.0.0`（字符串） |
| `entry` | ✅ | 卡片程序集文件名（与 csproj 的 `AssemblyName` 一致） |
| `icon` | 建议 | 同目录文件名（当前未渲染，保留） |
| `description` | 建议 | 一句话，卡片库显示 |
| `allowedSizes` | ✅ | 非空；**只能取** `1x1` / `2x1` / `1x2` / `2x2` |
| `defaultSize` | ✅ | 必须在 `allowedSizes` 内 |
| `maxInstances` | ✅ | ≥ 1；同类型卡片在容器里的实例上限 |
| `minAppVersion` | 建议 | 宿主版本门槛（当前记录，不做阻断） |

校验不通过 → 该卡片被跳过，卡片库显示**灰色占位 + 具体原因**，日志与系统气泡同时提示。

## 5. 源码工程（csproj 模板）

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0-windows</TargetFramework>
    <UseWPF>true</UseWPF>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <LangVersion>12</LangVersion>
    <AssemblyName>ClockCard</AssemblyName>          <!-- 必须等于 manifest.entry -->
    <RootNamespace>DsDock.Cards.Clock</RootNamespace>
    <EnableDefaultPageItems>false</EnableDefaultPageItems>
  </PropertyGroup>

  <ItemGroup>
    <ProjectReference Include="..\..\DsDock.Card.Abstractions\DsDock.Card.Abstractions.csproj">
      <!-- 契约由宿主提供：绝不能复制进插件目录，否则插件里的 ICardFactory
           和宿主里的会变成两个不同类型，加载时抛 InvalidCastException -->
      <Private>false</Private>
      <ExcludeAssets>runtime</ExcludeAssets>
    </ProjectReference>
  </ItemGroup>
</Project>
```

### 三条硬规则

1. **不要引用宿主程序集**（`DsDock.dll`）。卡片只引用 `DsDock.Card.Abstractions`
2. **不要把 `DsDock.Card.Abstractions.dll` 拷进 `Cards/<id>/`**（构建脚本会断言，出现即报错）
3. **DLL 里必须有一个 public、无参、实现 `ICardFactory` 的类型**

## 6. 契约 API 全表（`DsDock.Card.Abstractions`）

### `ICardFactory`

```csharp
public interface ICardFactory
{
    string Id { get; }        // 必须等于 manifest.id
    ICard Create();           // 每次"添加卡片"调用一次
}
```

### `ICard`（一次实例）

```csharp
public interface ICard
{
    FrameworkElement View { get; }                             // 你的 UI 根元素
    void OnAttached(ICardContext context);                     // 被放进容器时
    void OnSizeChanged(CardSize size);                          // 尺寸变化时（必须适配）
    void OnDetached();                                          // 被移出容器时（停掉计时器等）
    IReadOnlyList<CardMenuItem> GetMenuItems()                  // 可选：贡献右键菜单项
        => Array.Empty<CardMenuItem>();
}
```

### `ICardContext`（宿主给卡片的能力）

```csharp
public interface ICardContext
{
    Color Accent { get; }                       // 当前强调色（跟随设置）
    double FontSize { get; }                    // 当前字号（12–20）
    CardSize Size { get; }                       // 当前占用格数

    void RequestResize(CardSize size);          // 请求改尺寸（宿主做布局约束/动画）
    void RequestRemove();                       // 请求把自己移出容器（数据保留）
    void SaveState(string json);                // 存自己的状态（宿主落盘）
    string LoadState();                         // 读回来（没有则空串）
    IEditorPopup ShowPopup(string title, FrameworkElement content);  // 宿主弹窗
    bool Notify(string title, string message);    // 通过宿主发 Windows 系统通知（托盘气泡）
    void Log(string message);                     // 写一行到宿主日志（data/logs）
}
```

### 其它类型

```csharp
public sealed record CardSize(int Columns, int Rows);      // CardSize.Parse("2x1") / TwoByOne 等
public sealed record CardMenuItem(string Label, Action? Invoke, bool Checked = false);
public interface IEditorPopup { void Close(); bool IsOpen { get; } }
```

### 贡献右键菜单（推荐做法）

```csharp
public IReadOnlyList<CardMenuItem> GetMenuItems() => new[]
{
    new CardMenuItem("编辑", OpenEditor),
    new CardMenuItem(_done ? "标记未完成" : "标记完成", ToggleDone),
};
```

宿主会把你的项排在「更改尺寸 / 移除卡片」**之前**，并用同一套自绘菜单渲染。

### 弹窗（编辑界面）

**不要在卡片里自己 `new Window()`** —— 把内容交给宿主：

```csharp
IEditorPopup? popup = null;
popup = _context.ShowPopup("编辑便利贴", BuildEditorContent(() => popup));
// 内容里自己做"保存/取消"，保存后 popup.Close()
```

宿主负责：置顶、点外部关闭、Esc 关闭、淡入 + 上浮 150ms、在鼠标附近弹出并夹回工作区、跟随主题样式。

## 7. 生命周期与时序

```
添加卡片                    尺寸变化               移除卡片
ICardFactory.Create()
  → ICard 构造（只建 UI，不读状态）
  → OnAttached(context)      ← 在这里 LoadState + 首次渲染 + 启动计时器
  → OnSizeChanged(size)      ← 每次尺寸变化都会调用（含首次？否：首次用 context.Size）
  → ...（用户交互）
  → OnDetached()             ← 停计时器、提交未保存内容、清引用
     （状态文件保留：spec 要求"移除后数据保留"）
```

- **状态只在用户改动时 `SaveState`**，不要每秒写盘
- `OnDetached` 之后不要再访问 `_context`

## 8. 尺寸与布局

- 容器网格：**2 列 × 1…12 行**（上限随屏幕自适应，不超过 2×12）
- 每格 **160 DIP**，格间距 8，容器内边距 12
- 卡片可选尺寸：**1×1、2×1、1×2、2×2**（`allowedSizes` 里声明你支持哪些）
- 卡片在容器中的位置由**宿主**决定（拖动、吸附、回弹、防重叠都是宿主的事），卡片不要自己算坐标

**必须适配尺寸**：`OnSizeChanged` 里按 `size.Columns/Rows` 调整字号与排布。参考时钟卡片：

```csharp
public void OnSizeChanged(CardSize size)
{
    _size = size;
    bool wide = size.Columns >= 2;
    _time.FontSize = wide ? baseSize * 2.25 : baseSize * 1.35;   // 窄卡片必须缩小，否则溢出
    Refresh();
}
```

## 9. 状态持久化

- `SaveState(json)` → 宿主写到 `data/cards/<instanceId>.json`（原子写）
- `LoadState()` → 读回；文件不存在返回 `""`
- **建议带版本号并容错**：

```csharp
private void Save() => _context?.SaveState(JsonSerializer.Serialize(new State { V = 1, Text = _text }));

private void Restore(string json)
{
    if (string.IsNullOrWhiteSpace(json)) return;
    try { var s = JsonSerializer.Deserialize<State>(json); if (s != null) _text = s.Text ?? ""; }
    catch { /* 状态损坏时用默认值，绝不让卡片崩掉 */ }
}
```

- 数据包导出/导入时，你的状态文件会**自动**一起打包（无需额外处理）
- "移除卡片"不会删状态文件；真正的"删除数据"由卡片自己在保存时清空

## 10. 视觉规范

| 项 | 规范 |
|---|---|
| 卡片外框 | **宿主提供**：1px 半透明白边 + 圆角 8。**不要自己再铺一层满底色**（除非卡片语义需要，例如色卡） |
| 内边距 | 内容留 ≥10px，避免贴边；左上/右上若有元素（状态点、关闭按钮），内容区上边距加大（如 22px） |
| 字体 | 用 `context.FontSize` 作为基准；标题 ≈ 1×、次要信息 ≈ 0.8×、大数字可 2×以上 |
| 颜色 | 强调色用 `context.Accent`；文字用 `#F0FFFFFF`（主）/`#88FFFFFF`（次），保证在任何壁纸上都可读 |
| 动画 | 跟随宿主 60 FPS；短反馈 120–150ms，明显变化 200ms，缓动 `CubicEase/EaseOut` |
| 交互 | 右键菜单项交给宿主渲染；危险操作要二次确认（宿主已有自绘确认面板的先例） |
| **按钮悬停** | 卡片内的按钮请统一套用 `WireHover(border)`（鼠标进入 → 边框变强调色，离开恢复）；**新增按钮必须调用**，才能与宿主按钮观感一致（宿主侧对应 `DsHover.Enable(button)`，见便利贴卡片的实现） |

## 11. 踩坑清单（都是我们真实踩过的）

| 坑 | 现象 | 正解 |
|---|---|---|
| **透明 Panel 不可命中** | 双击/悬浮没反应，只有文字上有效 | 任何要接收鼠标事件的容器都要设 `Background = Brushes.Transparent`（`null` 不参与命中测试） |
| **`Border` 只有一个 `Child`** | `border.Children.Add(...)` 编译不过 | 用外层 `Grid`/`Canvas` 叠加多个元素 |
| **悬浮切换可见性会闪烁** | 元素"闪一下就消失" | 显示/隐藏改变了命中对象 → 触发 `MouseLeave` → 又隐藏；改为常显，或用光标轮询 |
| **`TextBox` 的类处理器吃掉回车** | `KeyDown` 里拦不到 Enter（永远换行） | 用 `PreviewKeyDown`（隧道，先于类处理器） |
| **`out` 参数不能被 lambda 捕获** | `CS1628` | 先赋给局部变量 `Action t = ...; out = t;` |
| **区域格式** | 日期/时间永远是美式 | 别开 `<InvariantGlobalization>true</InvariantGlobalization>`；用 `CultureInfo.CurrentCulture` 的格式 |
| **非 ASCII 符号传参损坏** | 图标字符变成 `?` | `FrameworkElement.Name` 不接受非 ASCII；跨脚本传中文/符号要小心编码（`.ps1` 一律纯 ASCII） |
| **WPF 与 Win32 显隐状态不一致** | 隐藏后 `Show()` 无效、状态判断错 | 统一走一个 `SetVisible`：同时 `Hide()/Show()` 与 `ShowWindow` |
| **大字号 + 1×1 溢出** | 内容被裁切 | 窄卡片下调字号/换更短格式 |
| **右键菜单弹不出来** | 卡片在 `MouseRightButtonUp` 里设了 `e.Handled = true`，事件不再冒泡到宿主的卡片壳 | 右键**不要**设 `Handled`（或不订阅右键），让宿主收到 |
| **托盘左右键无反应** | `NOTIFYICON_VERSION_4` 的布局是：`wParam` = 锚点坐标（低字 x、高字 y），**`lParam` 低字 = 事件**（`NIN_SELECT`/`WM_CONTEXTMENU`/鼠标消息），高字 = 图标 id；拿消息 id 比对永远不成立 | 从 `lParam` 低字取事件、`wParam` 取坐标（旧协议则从 `wParam` 低字取鼠标消息） |

## 12. 构建、部署与调试

```powershell
# 构建（含所有已注册卡片）+ 把卡片暂存到 <仓库根>/Cards/<id>/
powershell -ExecutionPolicy Bypass -File build.ps1

# 构建 + 部署到工作区之外 + 启动（托盘图标需要 Medium 完整性，见下）
tools\deploy.cmd

# 全部自动化自检（49 条，数据隔离，不会动你的配置）
tools\validate.cmd
```

- 构建脚本对每张卡片的处理：`dotnet build` → 读 `manifest.json` → 目标目录 `Cards/<manifest.id>/` → 拷 `entry` + `manifest.json` + `icon` → **断言目录内没有 `DsDock.Card.Abstractions.dll`**
- **部署必须在工作区之外**（如 `D:\dsDock`）：从工作区路径启动的进程会被环境降为低完整性，托盘图标注册会被系统拒绝（UIPI err=5）
- 卡片日志：卡片**没有** `Log` API（契约刻意保持最小）。排查时用 `SaveState` 的内容 + 宿主日志（`data/logs/*.log` 里会记录卡片加载、创建、尺寸、状态保存）
- 自检里验证新卡片：注册/加载成功、坏清单被拒、添加/移除、maxInstances、尺寸轮换、菜单项 —— 参考 `Diagnostics/SelfTestM2.cs`

## 13. 新卡片提交检查清单

- [ ] `src/Cards/<名>/` 下有 csproj + 卡片代码 + `manifest.json` + `icon.png`
- [ ] csproj 的 `AssemblyName` == `manifest.entry`
- [ ] `manifest.id` == 目录名（暂存后）== `registry.json` 里的 id == `ICardFactory.Id`
- [ ] `allowedSizes` 只含 `1x1/2x1/1x2/2x2`，`defaultSize` 在其中
- [ ] 只引用 `DsDock.Card.Abstractions`（`Private=false` + `ExcludeAssets=runtime`）
- [ ] 卡片 UI 有明确 `Background`（否则收不到鼠标事件）
- [ ] `OnAttached` 里 `LoadState` 且**容错**；用户改动时 `SaveState`
- [ ] `OnSizeChanged` 里适配所有声明过的尺寸（含最窄的 1×1）
- [ ] `OnDetached` 里停掉计时器/动画
- [ ] 在 `registry.json` 注册，跑 `tools\validate.cmd` 全绿

## 14. 最小卡片示例（可直接照抄）

```csharp
using System.Windows;
using System.Windows.Controls;
using System.Windows.Media;
using DsDock.Card.Abstractions;

namespace DsDock.Cards.Hello;

public sealed class HelloCard : ICard
{
    private readonly TextBlock _text;
    private ICardContext? _context;

    public HelloCard()
    {
        _text = new TextBlock { HorizontalAlignment = HorizontalAlignment.Center,
                                VerticalAlignment = VerticalAlignment.Center,
                                Foreground = new SolidColorBrush(Color.FromArgb(0xF0, 0xFF, 0xFF, 0xFF)) };
        View = new Grid { Background = Brushes.Transparent, Children = { _text } };  // 透明但可命中
    }

    public FrameworkElement View { get; }

    public IReadOnlyList<CardMenuItem> GetMenuItems() => new[]
        { new CardMenuItem("打个招呼", () => { _text.Text = $"你好，{DateTime.Now:HH:mm:ss}"; }) };

    public void OnAttached(ICardContext context) { _context = context; OnSizeChanged(context.Size); }

    public void OnSizeChanged(CardSize size)
        => _text.FontSize = (size.Columns >= 2 ? 1.6 : 1.2) * (_context?.FontSize ?? 15);

    public void OnDetached() => _context = null;
}

public sealed class HelloCardFactory : ICardFactory
{
    public string Id => "hello";
    public ICard Create() => new HelloCard();
}
```

配 `manifest.json`（`id: "hello"`、`entry: "HelloCard.dll"`、`allowedSizes: ["1x1","2x1"]`），加入 `registry.json`，跑 `tools\validate.cmd` 即可在卡片库看到它。

# 附录 A：把卡片打包成"可手动安装"的文件夹

> 目的：把一张卡片交给别人（或装到另一台机器），对方**不需要重新构建宿主**，只要拷一个文件夹 + 改一行配置 + 重启。
> （第 2 节的"运行时目录布局"就是安装后的形状；本附录讲**打包前**要挑哪些文件、必须排除哪些。）

## A.1 安装后的目标位置

```
<应用根>\Cards\<manifest.id>\
    ├─ manifest.json        必须
    ├─ <manifest.entry>     必须（文件名必须与 manifest.entry 完全一致，如 HelloCard.dll）
    └─ icon.png             建议（manifest.icon 指向它；当前版本只记录、暂未渲染）
```
示例：`D:\dsDock\Cards\hello\manifest.json` + `D:\dsDock\Cards\hello\HelloCard.dll`

**目录名必须等于 `manifest.id`** —— 宿主是按 `Cards\<registry 里的 id>\` 去找的，目录名不对就等于没装。

## A.2 打包（分发）形态

在卡片工程里构建一次，然后从输出目录挑文件，组成一个"卡片包"文件夹并压成 zip：

```
hello-card-1.0.0.zip
└─ （解压后直接就是）manifest.json + HelloCard.dll + icon.png
```
- **不要多套一层目录**：解压后应直接看到 `manifest.json`，否则安装时容易拷错层级
- 建议 zip 名带 id 与版本，例如 `hello-card-1.0.0.zip`

### 必须放进包里
| 文件 | 说明 |
|---|---|
| `manifest.json` | 卡片清单（第 4 节的字段与校验规则） |
| `<entry>.dll` | 卡片本体（`AssemblyName` 必须等于 `manifest.entry`） |
| `icon.png` | 可选，建议带 |

### 绝对不能放进包里
| 文件 | 原因 |
|---|---|
| `DsDock.Card.Abstractions.dll` | 契约由**宿主提供**。包里再带一份会导致插件里的 `ICardFactory` 与宿主里的变成两个不同类型 → 加载时 `InvalidCastException`（构建脚本也会断言失败） |
| 宿主程序集（`DsDock.exe`、`DsDock.dll` 等） | 卡片不允许依赖宿主 |
| 其它卡片的 DLL / 清单 | 一个包只装一张卡片 |
| `data\`、`settings.json`、`layout.json` | 那是用户数据，不属于卡片 |

### 视情况带（本项目卡片零第三方依赖，通常不需要）
| 文件 | 说明 |
|---|---|
| `*.deps.json` / `*.runtimeconfig.json` | 只有当卡片**自带第三方依赖**时才需要一起带；本项目卡片零依赖，无需带 |
| `*.pdb` | 调试符号，带了没坏处，分发时可以不带 |

## A.3 手动安装（4 步）

1. **拷贝目录**：把 `hello\`（含 `manifest.json`、`HelloCard.dll`、`icon.png`）拷到应用根：
   ```
   D:\dsDock\Cards\hello\
   ```
2. **注册 id**：编辑应用根的 `registry.json`，在 `cards` 数组里加上 id（**少了这一步，卡片目录存在也不会被加载**）：
   ```json
   { "cards": ["clock", "sticky_note", "hello"] }
   ```
   *（UTF-8 保存；数组语法别写错，解析失败会在日志里报"损坏"）*
3. **重启应用**（宿主只在启动时读一次 `registry.json`，目前不支持热加载）
4. **验证**：`<应用根>\data\logs\` 最新日志应出现三行：
   ```
   registry.json 注册卡片 3 个: clock, sticky_note, hello（部署根 …，插件目录 …\Cards）
   卡片清单校验通过: hello (你好 v1.0.0, 允许 1x1/2x1)
   卡片加载成功: hello → DsDock.Cards.Hello.HelloCardFactory @ HelloCard.dll
   ```
   然后打开**卡片库（▦）**即可看到并添加。

## A.4 安装失败时的表现与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 卡片库**没有**这一项 | `registry.json` 里没加 id / 应用没重启 | 补 id 并重启 |
| 卡片库出现**灰色占位 + 原因** | 清单校验没过（缺字段、`allowedSizes` 非法、`defaultSize` 不在其内、目录名与 id 不一致…） | 按第 4 节核对清单字段 |
| 占位原因显示**加载失败** | `entry` 文件名写错 / DLL 缺依赖 / 包里带了 `DsDock.Card.Abstractions.dll`（类型身份冲突） | 核对 `entry`、清掉契约 DLL |
| 其它卡片不受影响 | —— | 这是**失败隔离**：一张卡片坏掉只跳过它，并弹一次系统气泡提示 |

## A.5 与"部署脚本"的关系

- `tools\deploy.cmd` 用 `Copy-Item` 拷贝 `registry.json` 与整个 `Cards\`，是**复制**而不是镜像同步：
  - 手动装进部署根的第三方卡片**不会被下次部署删掉**
  - 但**同 id** 的卡片会被仓库内构建出来的版本覆盖
- 两种思路都可行：①卡片源码放进仓库 `src\Cards\` + `registry.json`，每次构建部署都会带上（推荐自己的卡片）；②手动装文件夹（推荐别人的卡片 / 临时试用）

## A.6 一分钟自查（打包发出去之前）

- [ ] 解压后**第一层**就能看到 `manifest.json`、`<entry>.dll`、（可选）`icon.png`
- [ ] `<entry>.dll` 文件名 == `manifest.entry` == csproj 的 `AssemblyName`
- [ ] `manifest.id` == 安装后的目录名（`Cards\<id>\`）
- [ ] `manifest.json` 字段齐全：`id/name/version/entry/allowedSizes/defaultSize/maxInstances`
- [ ] `allowedSizes` 只含 `1x1 / 2x1 / 1x2 / 2x2`，且 `defaultSize` 在其中
- [ ] 包里**没有** `DsDock.Card.Abstractions.dll`、没有宿主程序集、没有别的卡片
- [ ] 代码里有 `public`、无参、实现 `ICardFactory` 的类型
- [ ] 本地照 A.3 装一遍能正常出现在卡片库（这一步别省）
